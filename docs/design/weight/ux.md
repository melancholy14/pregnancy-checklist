# UX 스펙 — 체중 트래커

> 대상 영역: 체중 (`/weight`) — 임신 중 체중 기록 + 차트 + 권장 범위 안내
> 페르소나/원칙: [../persona.md](../persona.md)
> 시각 토큰/UI 매핑: [ui.md](ui.md)

---

## 1. 한 줄 정의

**임신 전 체중 기준 권장 증가 범위(11.5~16kg)와 함께, 본인의 체중 추이를 한눈에 보는 개인 트래커.** 의료적 진단 도구가 아니라 **검진 보조용**임을 명시. Phase 5 BMI별 개인화 강화 전 단계.

---

## 2. 사용자 목표 (Jobs-to-be-Done)

| 시점 | 사용자 의도 | 체중 트래커가 해줘야 하는 것 |
|------|-------------|------------------------------|
| **첫 기록** | "임신 시작 체중을 남겨두자" | 빈 상태에서 FAB → 폼 → 1회 입력으로 첫 데이터 생성 |
| **주간 기록** | "이번 주 체중 적어두자" | 빠른 입력(FAB → 날짜 자동 today + kg만) |
| **추이 확인** | "지금 정상 범위인가?" | 라인 차트 + 권장 하한/상한 ReferenceLine |
| **검진 준비** | "다음 진료에서 의사한테 보여주자" | 시간순 로그 리스트, 공유 가능한 차트 시각 |
| **잘못 입력** | "어제 잘못 적었어" | 로그 행에서 삭제 (편집은 미지원 — 결정 필요) |

핵심 행동 = **체중 입력**. 차트와 로그는 입력의 보상.

---

## 3. 정보 구조 (IA)

```
/weight
├─ Header (h1 + PageDescription with 의료 면책)
├─ WeightChart (데이터 ≥ 1개 시)
│   ├─ 라인 차트 (240px 높이)
│   ├─ ReferenceLine min (mint 대시)
│   ├─ ReferenceLine max (peach 대시)
│   └─ 설명 + 출처 + 면책 (3단)
├─ WeightForm (showAddForm === true)
│   └─ 날짜 + kg 입력 + 제출
├─ Empty state (📊 + 안내) [데이터 0개일 때]
│   └─ 또는 로그 리스트 (역순)
├─ 관련 글 카드 (peach surface, /articles/pregnancy-weight-management)
└─ FAB (입력 폼 토글)
```

### 3.1 차트 우선 IA

- **차트가 페이지의 중심**. 입력 폼은 토글 가능, 로그는 보조.
- 데이터 0개일 때 차트 영역은 `null` → 즉시 빈 상태로 대체.
- 데이터 1개일 때도 차트 표시 (점 1개) — 시작점 보존.

## 4. 상태 모델

| 상태 | 발생 조건 | 처리 |
|------|----------|------|
| **미하이드레이션** | 첫 렌더 | 빈 배열로 처리. 차트 안 그림. |
| **데이터 0개** | 입력 전 | 📊 + "아직 기록이 없어요" + FAB 강조 |
| **데이터 1개** | 첫 기록 후 | 차트에 점 1개 + 권장 범위 ReferenceLine. baseWeight = 첫 기록값 |
| **데이터 2개+** | 누적 후 | 라인 + 범위 표시 |
| **입력 폼 열림** | FAB 클릭 | WeightForm 페이지 안에 인라인. 모달 아님 |
| **입력 검증 실패** | 30~200kg 외 / 미래 날짜 | sonner toast 알림. 폼은 안 닫힘 |
| **삭제 호버** | 로그 행 hover | 휴지통 버튼 opacity 0 → 100 |
| **삭제 실행** | 휴지통 클릭 | 즉시 제거. **undo 미제공 — 결정 §10** |

### 4.1 baseWeight 정책

- baseWeight = **로그의 가장 이른 날짜의 weight**. 사용자가 "임신 전 체중"을 별도로 입력하지 않음.
- 권장 범위 = baseWeight + 11.5 ~ +16 kg (정상 BMI 가정).
- **개인 BMI 미반영** — Phase 5에서 강화 예정. 면책 카피로 명시.

## 5. 인터랙션 패턴

### 5.1 입력

- **트리거**: FAB → 인라인 폼 펼침
- **기본값**: 날짜 = today
- **검증**: 30~200kg, 미래 날짜 금지
- **제출**: store에 추가 (날짜 오름차순 자동 정렬) + GA `weight_log` + 폼 초기화 + 닫힘
- **GA 파라미터**: 날짜·체중·delta from last 검토

### 5.2 차트 인터랙션

- **Recharts 기본 툴팁**: hover 시 데이터 포인트 + kg 값.
- **active dot**: hover 시 r=4 → r=6.
- **차트 줌·팬 없음**: 단순 시계열만.
- **반응형**: ResponsiveContainer 자동.

### 5.3 삭제

- 로그 행 hover → 휴지통 노출 → 클릭 → 즉시 삭제.
- **확인 다이얼로그 없음** — 실수 위험. UX §10 결정.

### 5.4 관련 글 클릭

- 카드 통째로 `<Link>`. `/articles/pregnancy-weight-management` 등.

## 6. 접근성 스펙

| 항목 | 합격 기준 |
|------|-----------|
| **키보드 입력** | FAB → date input → number input → 제출 버튼. Tab 순서 명확. |
| **차트 스크린리더** | 데이터 테이블로 fallback 또는 ARIA label로 "체중 추이 차트, N개 데이터" |
| **터치 타겟** | FAB 56×56. 로그 행 ≥ 44px. 휴지통 버튼은 hover-only라 모바일에서는 항상 노출 검토 |
| **입력 검증** | 검증 실패 시 toast + aria-live 영역 |
| **색 대비** | 차트 라인(현재 pink)이 ReferenceLine과 시각적으로 구분되는지 — 색맹 안전성 검토 |

## 7. 마이크로카피 원칙

- **의료 면책 우선**. PageDescription에 "정기 검진 때 담당 의료진과 함께"로 시작.
- **차트 하단 3단 구조**: 권장 범위 / 출처(대한산부인과학회) / 면책(*).
- **빈 상태**: "아직 기록이 없어요" + 격려 ("첫 기록을 남겨보세요").
- **단위 통일**: kg, 소수점 1자리.
- **이모지**: 📊(빈 상태), 헤더에는 사용 안 함(의료 도구 톤).

---

## 8. 데이터·저장 모델 (UX 관점)

- **logs**: localStorage `weight-storage` (Zustand persist).
- **WeightLog 타입**: `{ id, date (ISO 8601), weight (number) }`.
- **정렬**: 추가 시 date 오름차순 자동.
- **삭제**: id로 필터링.
- **편집 미지원**: 편집은 삭제 후 재입력으로 우회 — UX 마찰 결정.
- **마이그레이션**: BMI 추가 시 weightLog에 baselineBmi 또는 별도 metadata 추가 가능. 기존 데이터 호환 확보 필요.

## 9. 성공 측정

| UX 가설 | 측정 이벤트 |
|---------|-------------|
| 첫 기록을 남긴다 | `weight_log { is_first: true }` |
| 주간 1회 이상 기록한다 | `weight_log` 주간 발사율 (재방문 강한 신호) |
| 권장 범위를 인지한다 | 차트 노출 시간(scroll dwell) + 면책 텍스트 노출 |
| 관련 글로 분기한다 | `related_article_click { from: "weight" }` |
| 삭제 실수가 발생한다 | (현재) 측정 어려움 — 삭제 후 즉시 재입력 패턴 추적 검토 |

## 10. 알려진 UX 이슈 / 결정 대기

> UI 측 위반 트래커: [ui.md §10](ui.md)

- [ ] **(M)** 삭제 confirm 다이얼로그 / undo 토스트 추가 — 현재 즉시 삭제, 실수 복구 불가
- [ ] **(M)** 편집 기능 (날짜/체중) 추가 여부 — 현재는 삭제 후 재입력으로 우회
- [ ] **(M)** baseWeight 정책 — "임신 전 체중"을 별도 입력받을지, 첫 기록을 그대로 쓸지 (Phase 5 BMI 강화와 묶임)
- [ ] **(L)** 휴지통 버튼이 hover-only — 모바일 사용자에게 발견성 문제. 항상 노출하거나 long-press 패턴 검토
- [ ] **(M)** 차트 라인 색이 pink (CTA 토큰) — peach(data) 토큰으로 변경 검토 (UI §10과 묶임)
- [ ] **(L)** 차트 텍스트 라벨 (권장 하한/상한)이 차트 우측에 잘림 모바일에서 검증
- [ ] **(M)** Phase 5 BMI 개인화 — 사용자가 임신 전 BMI 카테고리(저체중/정상/과체중/비만)를 선택하면 권장 범위가 달라짐. 데이터 모델·UI 양쪽 결정 필요
