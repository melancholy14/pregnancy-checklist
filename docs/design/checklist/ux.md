> 대상 영역: 체크리스트 허브(`/checklist`) + 출산가방·남편준비·임신준비 3종 + 타임라인 연동
> 페르소나/원칙: [persona.md](../persona.md)
> 시각 토큰/UI 매핑: [ui.md](ui.md)
> 알려진 위반/개선 백로그: [../phase-4.5/plan.md §2](../../plan/phase-4.5.md)

## 1. 한 줄 정의

**임신부터 출산까지의 준비를 "지금 챙길 것 → 챙긴 것 → 남은 것"으로 보여주고, 사용자가 자신의 주차에 맞춰 자율적으로 채워나가는 도구.**

타임라인이 "주차순으로 알려주는 가이드"라면, 체크리스트 3종은 "목적별로 빠짐 없이 챙기게 해주는 작업 도구". 둘을 같은 허브에서 한 번에 본다.

---

## 2. 사용자 목표 (Jobs-to-be-Done)

| 시점 | 사용자 의도 | 체크리스트가 해줘야 하는 것 |
|------|-------------|------------------------------|
| **임신 초기 (~20주)** | "지금 시작해도 될 만한 게 있나?" | 임신 준비 체크리스트로 등록·검사·생활습관 안내 |
| **임신 중기 (20~32주)** | "남편/파트너랑 같이 챙길 게 뭐지?" | 남편준비 체크리스트로 동행 가능한 항목·정보 노출 |
| **출산 임박 (32~40주)** | "병원 갈 때 뭘 들고 가지?" | 출산가방 체크리스트로 누락 0 보장 |
| **상시** | "이번 주차에 뭘 해야 하지?" | 타임라인이 주차별 체크 항목 제공 |
| **상시** | "내 진척도 한눈에 보고 싶다" | 허브의 4개 카드 진행률 미리보기 |

핵심 행동 = **체크 토글**. 이 한 동작이 재방문의 가장 강한 신호이자 가치 전달 시점.

## 3. 정보 구조 (IA)

```
/checklist (허브)
├─ 주차별 타임라인 카드 ──→ /timeline
├─ 출산가방 체크리스트 카드 ──→ /checklist/hospital-bag
├─ 남편준비 체크리스트 카드 ──→ /checklist/partner-prep
└─ 임신준비 체크리스트 카드 ──→ /checklist/pregnancy-prep

/checklist/[slug]
├─ Header (h1 + description + ShareButton)
├─ 진행률 카드 (전체 + 서브카테고리 분해 + 25/50/75/100 마이크로카피)
├─ 섹션 (서브카테고리별)
│   └─ 항목 행 × N (체크박스 + 타이틀 + 노트 + 우선순위 배지 + 커스텀 액션)
├─ 관련 콘텐츠 (글 / 타임라인 / 영상)
└─ FAB: 항목 추가
```

### 3.1 위계 원칙

- **허브 = 메뉴이자 진척도 대시보드**. 카드 안에 진행률 바 + N/M 카운트가 들어가서, 진입 전에 "어디부터 손댈지" 결정 가능.
- **상세 = 작업 화면**. 한 화면에서 진행률·작업·관련 콘텐츠·추가 4가지가 모두 끝남. 별도 모달로 빠지지 않음.
- **타임라인 카드는 동급이 아니라 1.2배 강조**. 4종 중 메인 도구라는 위상을 시각·문구로 전달 (단, 강조 수단이 pink full-bleed면 CTA 신호와 충돌 — [phase-4.5 §2.4 M5·M6](../../plan/phase-4.5.md) 참고).

---

## 4. 상태 모델

화면을 그릴 때 항상 아래 상태 4종을 모두 고려한다.

| 상태 | 발생 조건 | 처리 |
|------|----------|------|
| **미하이드레이션** | localStorage 읽기 전 첫 렌더 | `hydrated=false`. checked 카운트는 0으로 표시. 진행률 바 0%. **핵심: 깜빡임/점프 금지** — 0에서 N으로 점프해도 시각적으로 부드럽게. |
| **체크 0개** | 첫 방문, 또는 전체 해제 | "순조로운 출발!" 마이크로카피는 25%↑ 부터. 0%일 때는 격려 카피 없이 깔끔. |
| **체크 진행 중** | 1개 이상 체크, 100% 미만 | 25/50/75 마일스톤마다 카피 변경. 체크된 행은 mint/20 배경 + line-through. |
| **체크 100%** | 전 항목 체크 | "완벽하게 준비되었어요! 🎊" — 컨페티는 검토 후 도입. |

### 4.1 항목 행의 부가 상태

- **편집 중** (`isCustom` 항목만): 인라인 편집 폼으로 전환. 다른 행 클릭 시에도 편집 모드 유지(저장/취소 명시 필요).
- **삭제 확인 다이얼로그 열림**: 한 화면에 1개만.
- **노트 표시**: 현재는 미체크 상태에서만 표시 — **체크 후에도 노트는 살리는 쪽이 정보 보존**([phase-4.5 §2.4 M4](../../plan/phase-4.5.md)에서 결정 대기).

## 5. 인터랙션 패턴

### 5.1 체크 토글

- **트리거**: 행 클릭 / 체크박스 클릭 / 키보드 Enter·Space 모두 동일 결과.
- **피드백**: 즉시 시각 반영(mint/20 배경 + 취소선) + 진행률 바 width 트랜지션 + GA `checklist_check` 발사.
- **WCAG 4.1.2 주의**: 현재 행이 `role="button"` div인데 내부에 진짜 인터랙티브 요소가 있어 위반 — 마크업을 `<label>` 기반으로 재설계 필요([phase-4.5 §2.4 M1](../../plan/phase-4.5.md)).

### 5.2 항목 추가

- **트리거**: FAB(우하단)
- **흐름**: FAB 클릭 → 인라인 폼 노출 → 분류 선택 + 제목 입력 → 추가하기 → 폼 닫힘
- **자동 기본값**: priority=`medium`, recommendedWeek=0, isCustom=true
- **엣지**: 빈 제목·미선택 분류는 비활성. subcategories가 0개면 폼 자체가 안 뜸(JSON 데이터 오류 fallback).

### 5.3 항목 편집 / 삭제

- **편집**: 커스텀 항목만 가능. 현재는 title만 수정 가능 — priority/note 수정 허용 여부는 [phase-4.5 §3 P1](../../plan/phase-4.5.md)에서 결정 대기.
- **삭제**: DeleteConfirmDialog 거쳐야 실행. **현재 undo 토스트 없음** — 실수 복구 불가([phase-4.5 §2.6 #4](../../plan/phase-4.5.md)).

### 5.4 공유

- **트리거**: 페이지 우상단 ShareButton
- **모바일**: Web Share API 네이티브 시트
- **데스크톱**: Clipboard API + 토스트
- **GA**: `share_click { method, slug }`

### 5.5 관련 콘텐츠 클릭

- **글**: SPA navigation (`<Link>`)
- **타임라인 / 영상**: hash anchor가 들어간 cross-page는 `<a>` 풀 내비게이션 — Next.js 16.2 App Router 해시 누적 버그 회피([ChecklistRelatedContent.tsx 주석](../../../src/components/checklist/ChecklistRelatedContent.tsx#L7-L8))

## 6. 접근성 스펙 (필수 합격선)

| 항목 | 합격 기준 |
|------|-----------|
| **키보드 내비** | 모든 행: Tab으로 도달, Enter/Space로 토글. FAB: Tab으로 도달. 편집 폼: 입력 즉시 autoFocus. |
| **스크린리더** | 행 라벨: "{title}, 체크" / "{title}, 체크 해제". 체크박스 단독 라벨도 명시. 우선순위 배지는 텍스트로 읽힘. |
| **색 대비** | foreground(`#3D4447`) on pastel/30~/60: WCAG AA 통과. 단, mint/20 배경 + muted-foreground 취소선 텍스트는 대비 측정 필요. |
| **인터랙티브 중첩** | 인터랙티브 요소가 인터랙티브 요소를 감싸지 않음. (현재 위반 — [phase-4.5 §2.4 M1](../../plan/phase-4.5.md)) |
| **focus visible** | 모든 인터랙티브 요소에 `focus:ring-2 focus:ring-ring` 또는 동등. |
| **터치 타겟** | 최소 40×40px. FAB 56×56. 행 패딩으로 44px 이상 확보. |

## 7. 마이크로카피 원칙

- **존댓말 + 친근한 평어 혼용 금지**. 본 제품은 존댓말 통일.
- **격려 > 지시**. "체크하세요"보다 "순조로운 출발!" "절반 완료!" 스타일.
- **숫자는 분수**: "8/32 완료". 백분율은 진행 바 자체로 충분.
- **부정형 회피**. "아직 못한 항목"보다 "남은 항목".
- **이모지는 신호용 1개만**. h1 옆 ✅, 100% 도달 시 🎊. 배지·본문·서브카테고리에는 사용 금지.
- **항목 타이틀**은 사용자가 쓴 그대로 line-through. 노트는 회색 + 보조 정보로.

## 8. 데이터·저장 모델 (UX 관점)

- **체크 상태는 기기에 저장** — localStorage. 회원가입 없음.
- **3종 + 타임라인은 독립 store** — 한 곳에서 체크해도 다른 체크리스트에 영향 없음.
- **커스텀 항목 ID**: `custom-{slug}-{timestamp}`. 충돌 가능성은 무시 가능.
- **마이그레이션 위험**: priority/note 데이터 모델 변경 시 기존 커스텀 항목 호환성 확보 필요(읽기는 옵셔널, 쓰기만 새 필드).
