# UX 스펙 — 타임라인

> 대상 영역: 타임라인 (`/timeline`) — 4~40주차 임신 주차별 가이드 + 체크리스트
> 페르소나/원칙: [../persona.md](../persona.md)
> 시각 토큰/UI 매핑: [ui.md](ui.md)
> 체크리스트 영역과의 짝: [../checklist/ux.md](../checklist/ux.md)

---

## 1. 한 줄 정의

**임신 4주~40주를 시계열로 펼쳐주고, 각 주차에 무엇을 해야 하는지 카테고리·체크리스트로 알려주는 마스터 가이드.** 체크리스트(허브)가 "목적별 작업 도구"라면, 타임라인은 "시간순 가이드". 같은 체크 메커니즘을 공유하지만 IA가 정반대.

---

## 2. 사용자 목표 (Jobs-to-be-Done)

| 시점 | 사용자 의도 | 타임라인이 해줘야 하는 것 |
|------|-------------|---------------------------|
| **현재 주차 확인** | "지금 24주차인데 뭘 해야 해?" | 진입 시 현재 주차 카드로 자동 스크롤 + 강조 |
| **앞 주차 미리 보기** | "30주차에는 뭘 준비해?" | 미래 카드도 펼쳐 볼 수 있되 "current"와 시각 구분 |
| **지난 주차 회고** | "20주차에 뭐 했더라?" | past 카드 + 체크 상태 보존으로 회고 가능 |
| **카테고리별 보기** | "행정 절차만 모아 보고 싶어" | 카테고리 필터(prep/shopping/admin/education/wellbeing) |
| **개인화 추가** | "나만의 항목 추가하고 싶어" | FAB → 통합 추가 폼 (타임라인 항목 / 체크리스트 항목 둘 다) |

핵심 행동 = **체크 토글 + 카드 펼치기**. 타임라인은 holder, 체크 상태는 체크리스트 store와 공유.

---

## 3. 정보 구조 (IA)

```
/timeline
├─ DueDateBanner (예정일 미입력 시 안내)
├─ Header (h1 + description + ShareButton)
├─ 현재 주차 카드 (hydration 후)
├─ 전체 진행률 카드
├─ 첫 체크 배너 (1회성 onboarding)
├─ 카테고리 필터 + 행정 주의사항 패널
├─ 타임라인 메인 (세로 그라디언트 라인 + 주차별 카드)
│   └─ TimelineAccordionCard × N
│       ├─ 주차 원형 배지 (좌측 absolute)
│       ├─ 카드 헤더 (타입 배지 + 제목 + 체크 요약)
│       ├─ Collapsible 본문 (WeekChecklistSection)
│       └─ 관련 콘텐츠 (체크리스트/아티클/영상 링크)
├─ 기타 섹션 (주차 미지정 커스텀 항목)
├─ 최종 메시지 (40주 도달 축하)
└─ FAB (UnifiedAddForm)
```

### 3.1 시간축 시각화

- **세로 그라디언트 라인** (pink → lavender → yellow)이 4주~40주를 잇는 척추.
- **past / current / future** 3가지 시각 상태:
  - past: 일반 카드 + 체크 보존
  - current: `scale-110 ring-4 ring-white shadow-md` + 자동 스크롤 타겟
  - future: 일반 카드, 미체크는 자연스러움
- **현재 주차 자동 스크롤**: hydration 완료 후 IntersectionObserver로 위치 도달 → smooth scroll.

### 3.2 카테고리 필터

- 5개 타입(prep / shopping / admin / education / wellbeing) + "all".
- 필터 활성화 시 해당 타입 외 주차는 시각적으로 숨기거나 흐리게 (현재는 filteredWeekSet 기반).
- **주의**: 행정(admin) 필터에는 별도 안내 패널이 붙음 — 행정 절차의 시점 민감성 강조.

## 4. 상태 모델

| 상태 | 발생 조건 | 처리 |
|------|----------|------|
| **미하이드레이션** | 첫 렌더, localStorage 미적용 | 진행률 0%, 체크 0개. 자동 스크롤 보류. |
| **예정일 미입력** | dueDate 없음 | DueDateBanner로 입력 유도. 현재 주차 카드 비표시(또는 안내). |
| **현재 주차 진입 직후** | hydrated && currentWeek 산출됨 | 해당 주차로 자동 스크롤 + ring 강조. |
| **첫 체크 배너 표시** | localStorage에 표시 이력 없음 | 1회성 mint 배너. 닫으면 영구 숨김. |
| **카테고리 필터 적용** | activeCategory ≠ "all" | 해당 타입 외 카드 시각 변경. "기타 섹션"은 "all"일 때만 표시. |
| **편집 모드 (커스텀 항목)** | 사용자가 편집 클릭 | 인라인 편집 폼. 다른 행과 동시 편집 안 됨. |
| **40주 도달 / 출산 임박** | 마지막 카드 진입 | 최종 메시지 블록(축하). |

### 4.1 체크 상태 동기화

- **타임라인의 체크리스트 행**과 **/checklist/* 페이지의 같은 항목**은 **동일 store**(`useChecklistStore`)를 공유.
- 한쪽에서 체크하면 다른 쪽에 즉시 반영.
- 충돌·동시성 이슈 없음(localStorage + Zustand persist).

## 5. 인터랙션 패턴

### 5.1 카드 펼치기 / 접기 (Collapsible)

- **트리거**: 카드 헤더 영역 클릭. 본문은 직접 클릭으로 닫지 않음(체크 토글 보호).
- **피드백**: ChevronDown 회전 + 본문 슬라이드.
- **현재 주차 카드는 기본 펼침 상태**(권장) — hydration 후 사용자가 닫지 않으면 자동 펼침.

### 5.2 체크 토글

- WeekChecklistSection 내부, 체크리스트 영역과 동일한 컴포넌트 패턴.
- **WCAG 4.1.2 주의**: 체크리스트와 동일한 row-as-button 마크업 위반(상속). [checklist/ux.md M1](../checklist/ux.md)와 같은 결정으로 일괄 처리.

### 5.3 카테고리 필터

- 필터 버튼 그룹. 활성 버튼은 한 번에 하나(라디오 형태).
- 필터 변경 시 GA `category_tab_switch` 발사.
- **활성 색이 pink** — 데이터 라벨에 CTA 색 사용 위반 (UI §10).

### 5.4 통합 추가 폼 (UnifiedAddForm)

- FAB → 모달/시트 폼.
- **두 종류 추가 가능**: (a) 타임라인 주차 항목 (b) 체크리스트 항목.
- 라디오로 모드 선택 → 입력 필드가 모드에 따라 동적.
- **검증**: 주차 1~40, 제목 필수, 체크리스트 모드일 때만 카테고리.
- **엣지**: 사용자가 선택한 주차에 기본 타임라인 항목이 0개일 때 alert 다이얼로그(왜?를 명확히 할 결정 필요).

### 5.5 관련 콘텐츠 클릭

- 체크리스트 페이지 / 아티클 / 영상으로 이동.
- 같은 페이지(`/timeline`) 내 hash navigation은 풀 내비게이션(`<a>`) — Next.js 16.2 hash 누적 버그 회피.

## 6. 접근성 스펙

| 항목 | 합격 기준 |
|------|-----------|
| **키보드 내비** | 카테고리 필터 → 각 주차 카드 헤더 → (펼침 시) 체크리스트 행 → 다음 카드. Skip-to-current-week 링크 검토. |
| **스크린리더** | 주차 카드: "20주차, 영양 관리, 펼침" / "20주차, 영양 관리, 접힘". 체크 행은 체크리스트와 동일 패턴. |
| **자동 스크롤** | 사용자 의지로 스크롤 한 후엔 추가 자동 스크롤 금지(현재 1회성). |
| **색 대비** | past/current/future 시각 구분이 색에만 의존하지 않도록 — ring/scale도 동반(현재 OK). |
| **터치 타겟** | 카드 헤더(펼침 트리거) ≥ 44px 높이. FAB 56×56. |

---

## 7. 마이크로카피 원칙

- **시제는 현재 진행형**. "20주차에는 ___을 해요". (체크리스트는 명사 위주, 타임라인은 행위 위주.)
- **현재 주차 강조**: "이번 주가 ___ 주차예요" 또는 d-day 형태.
- **40주 도달**: "이제 곧 만나요!" 같은 감정적 카피. 체크리스트 100%와 톤 분리.
- **카테고리 라벨**: prep/shopping/admin/education/wellbeing은 한국어로 "준비/쇼핑/행정/교육/건강". 라벨 일관성은 데이터 layer(`TIMELINE_TYPE_CONFIG`)에서 관리.

---

## 8. 데이터·저장 모델 (UX 관점)

- **타임라인 항목 자체**: `timeline_items.json` (정적). 40주차까지의 표준 가이드.
- **타임라인 커스텀 항목**: `useTimelineStore` (localStorage `timeline-storage`).
- **체크 상태**: `useChecklistStore` (localStorage `checklist-storage`) — **체크리스트 영역과 공유**.
- **카테고리 필터 상태**: 컴포넌트 로컬 (페이지 이탈 시 초기화).
- **카드 펼침/접힘 상태**: 컴포넌트 로컬. 영구 보존 안 함.

## 9. 성공 측정

|---------|-------------|
| 사용자가 현재 주차에 도달한다 | `timeline_view { current_week }` (자동 스크롤 완료 후) |

| 통합 추가 폼이 쓰인다 | `custom_item_add { mode: timeline | checklist }` |

## 10. 알려진 UX 이슈 / 결정 대기

> UI 측 위반 트래커: [ui.md §10](ui.md)

- [ ] **(M)** 카테고리 필터 활성색이 pink (CTA 토큰)인지, lavender(secondary)로 바꿀지 — UI 결정과 묶임
- [ ] **(M)** 카드 헤더 클릭 = 펼침. 그런데 체크리스트 영역의 row-click = 체크 토글과 멘탈 모델 불일치 — 통일 결정 필요
- [ ] **(L)** 현재 주차 자동 스크롤이 사용자에게 "튕긴다"는 인상 줄 수 있음 — 스크롤 속도/타이밍 검토
- [ ] **(L)** "기타 섹션"(주차 미지정 커스텀)이 카테고리 필터 적용 시 사라지는 것이 사용자에게 명확한가 — 안내 보강 필요
- [ ] **(M)** UnifiedAddForm의 "타임라인 vs 체크리스트" 모드 선택을 사용자가 이해하는가 — 두 모드의 차이를 폼 안에서 한 줄로 설명 필요
- [ ] **(L)** 체크리스트와 동일 store 공유 — 한쪽에서 항목 삭제 시 다른 쪽 즉시 반영. 사용자에게 명시할지
