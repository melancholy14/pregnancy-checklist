# UX 스펙 — 베이비페어

> 대상 영역: 베이비페어 (`/baby-fair`) — 베이비페어 일정 목록 + 외부 사이트 진입
> 페르소나/원칙: [../persona.md](../persona.md)
> 시각 토큰/UI 매핑: [ui.md](ui.md)

---

## 1. 한 줄 정의

**베이비페어 행사 일정을 도시·시기별로 큐레이션해서 보여주고, 사용자를 공식 사이트로 안전하게 안내하는 디스커버리 도구.** 자체 콘텐츠가 아닌 외부 행사 정보 큐레이션 — 핵심 가치는 "여기에 다 모아져 있다" + "외부 사이트로 가는 길의 안전 마찰".

---

## 2. 사용자 목표 (Jobs-to-be-Done)

| 시점 | 사용자 의도 | 베이비페어 영역이 해줘야 하는 것 |
|------|-------------|----------------------------------|
| **현재 진행 중인 행사 찾기** | "지금 가볼 만한 페어 있나?" | "진행 중" 탭 + D-day 배지 |
| **앞으로의 일정 보기** | "다음 달 페어 일정 알고 싶어" | "예정" 탭 + 시간순 |
| **지난 행사 회고** | "지난 페어 어땠는지 보고 싶어" | "지난 행사" 탭 |
| **지역 필터** | "서울 페어만 보고 싶어" | 도시 필터 (펼침/접기) |
| **연도 필터** | "2025년 페어만" | 연도 select |
| **공식 사이트 방문** | "이 페어 자세히 보고 싶어" | 카드 클릭 → confirm 다이얼로그 → 외부 새 탭 |
| **참관 팁** | "처음 가는데 뭐 챙기지?" | 페이지 하단 5가지 팁 |

핵심 행동 = **카드 클릭 → confirm → 외부 사이트 진입**. 자체 페이지 안 머무는 대신 **밖으로 잘 보내는 것**이 가치.

## 3. 정보 구조 (IA)

```
/baby-fair
├─ Header (h1 "베이비페어 일정" + PageDescription)
├─ Empty state (이벤트 0개일 때)
├─ 필터
│   ├─ 연도 select (2개 이상의 연도가 있을 때만)
│   └─ 도시 필터 버튼 그룹 (펼침/접기 토글)
├─ 탭 (진행 중 / 예정 / 지난 행사) — 각 탭 카운트 배지
├─ 패널
│   ├─ 진행 중: BabyfairCard 그리드 + daysLeft (D-day)
│   ├─ 예정: BabyfairCard 그리드 (D-day 없음)
│   └─ 지난 행사: BabyfairCard 그리드 (D-day 없음)
└─ 참관 팁 카드 (5개 불릿 + 그라디언트 배경)
```

### 3.1 카드 메타데이터 (BabyfairCard)

```
[규모 배지] [도시 배지] [D-day 배지(진행 중)]
이벤트 이름 (h3)
📅 날짜 범위
📍 장소
🕐 운영 시간 (선택)
🎟️ 입장료 (선택)
🅿️ 주차 (선택)
• 하이라이트 최대 3개 + "외 N개"
💬 팁 박스 (선택)
─────
"상세 정보는 공식 홈페이지에서 확인하세요" 푸터
```

### 3.2 외부 진입의 마찰

- 카드 클릭 즉시 외부로 가지 않고 **AlertDialog**로 한 번 확인.
- "{이벤트명}" 제목 + "공식 홈페이지로 이동합니다" 설명.
- 취소 / 이동 두 버튼.
- 이동 시 새 창 + `window.opener = null` (보안).

## 4. 상태 모델

| 상태 | 발생 조건 | 처리 |
|------|----------|------|
| **이벤트 0개** | 데이터 비어있음 | 📋 + "아직 등록된 행사가 없어요" |
| **연도 1종** | events에 단일 연도만 | 연도 select 미표시 |
| **도시 필터 접힘** | 초기 | `max-h-[5.5rem]` 약 88px |
| **도시 필터 펼침** | "더보기" 클릭 | `max-h-[500px]` |
| **탭 전환** | 사용자 클릭 | 패널 즉시 교체. 필터는 유지. |
| **진행 중 탭** | start_date ≤ today ≤ end_date | D-day 배지 표시 |
| **예정 탭** | start_date > today | D-day 미표시 |
| **지난 탭** | end_date < today | D-day 미표시 |
| **카드 클릭** | hasUrl (`official_url` 존재) | AlertDialog 열림 |
| **카드 무효** | hasUrl 없음 | 시각적으로 구분 필요 — 현재 명확하지 않음 |
| **팝업 차단** | window.open returns null | sonner toast "팝업이 차단되었습니다" |

## 5. 인터랙션 패턴

### 5.1 필터

- **연도**: native `<select>`. 모바일 접근성 OK.
- **도시**: 버튼 그룹 + 펼침/접기. 한 번에 한 도시 선택(단일 선택). "전체"가 기본.
- **탭과 필터 독립**: 탭은 시점, 필터는 공간. 사용자가 둘을 동시에 좁힐 수 있음.

### 5.2 카드 클릭 → 다이얼로그 → 외부 진입

- **카드 트리거**: `role="button" tabIndex={0}` + onClick + onKeyDown(Enter/Space).
- **interactive 중첩 위반 없음** — 카드 자체가 button이고 내부에 별도 button 없음 ✓
- **다이얼로그 confirm 색**: `bg-accent-purple` (DESIGN.md 7.1 dialog action 패턴) — pink 충돌 회피 ✓
- **window.open 정책**:
  - target="_blank" + 새 창
  - `newWindow.opener = null` (COOP)
  - **`rel="noopener noreferrer"` 미명시** — `<a>` 사용 안 하므로 적용 불가, opener=null로 부분 완화

### 5.3 GA 트래킹

- `outbound_click { url, event_name }` — 외부 진입 측정. CTA 효율 핵심 지표.

## 6. 접근성 스펙

| 항목 | 합격 기준 |
|------|-----------|
| **키보드 내비** | 필터 → 탭 → 카드 그리드 → 다음 탭 → ... 명확한 순서 |
| **카드 활성화** | Enter/Space 모두 다이얼로그 열림 ✓ |
| **다이얼로그** | Radix AlertDialog 기본 — focus trap, ESC 닫힘, focus 복귀 ✓ |
| **외부 링크 표시** | "공식 홈페이지로 이동합니다" 명시 ✓. 새 창 열림 표시는 다이얼로그 텍스트로 충분 |
| **터치 타겟** | 카드 통째 — 충분. 필터 버튼 ≥ 36px. |
| **빈 상태** | 이모지 + 텍스트 — 추가 가이드 없음 |

---

## 7. 마이크로카피 원칙

- **D-day 표기**: "D-Day" / "D-{n}일 남음". 진행 중에만.
- **다이얼로그**: 짧고 명확. "이동" / "취소".
- **참관 팁**: 명사형이 아닌 동사형. "○○하세요" / "○○ 챙기세요".
- **푸터 안내**: "상세 정보는 공식 홈페이지에서 확인하세요" — 자체 데이터 한계 명시.
- **이모지**: 카드 메타 아이콘(📅📍🕐🎟️🅿️💬)는 정보 구분용으로 일관 사용.

## 8. 데이터·저장 모델 (UX 관점)

- **events**: `/src/data/babyfair_events.json` 정적, 50개 이상.
- **타입 BabyfairEvent**: slug, name, venue_name, city, start_date, end_date, official_url, review_status, scale?, admission?, parking?, highlights?, tip?, operating_hours?, pre_register_url? (미사용).
- **상태 분류 (today 기준)**:
  - ongoing: start_date ≤ today ≤ end_date
  - upcoming: start_date > today
  - ended: end_date < today
- **사용자 데이터 없음**. 페이지 이탈 시 필터/탭 초기화.
- **review_status**: 운영자용. 사용자 미노출.
- **pre_register_url**: 데이터에 있으나 미렌더 — 향후 feature 후보.

## 9. 성공 측정

| UX 가설 | 측정 이벤트 |
|---------|-------------|
| 외부 진입이 일어난다 | `outbound_click { event_name }` |
| 도시 필터가 쓰인다 | `filter_apply { type: city, value }` (현재 미정의) |
| 탭 전환이 일어난다 | `tab_switch { from, to }` (현재 미정의) |
| 다이얼로그에서 취소율 | `outbound_click` vs 다이얼로그 노출 비율 |
| 참관 팁이 읽힌다 | scroll dwell @ tips section |
| 참관 후 재방문 | 진행 중 → 예정 탭 전환 후 며칠 뒤 재방문 |

## 10. 알려진 UX 이슈 / 결정 대기

> UI 측 위반 트래커: [ui.md §10](ui.md)

- [ ] **(M)** `pre_register_url` 미사용 — 사전등록 링크 별도 노출 여부 (혜택 + GA 분리 가능)
- [ ] **(M)** `official_url` 없는 카드의 시각 구분 — 현재 클릭 무반응이라 사용자 혼란 가능
- [ ] **(L)** 도시 필터 다중 선택 — "서울+경기" 같은 광역 묶음 자주 발생

- [ ] **(M)** review_status === "pending" / "rejected" 처리 — 현재 다 표시하는지, 필터링하는지 명확화
- [ ] **(L)** 참관 팁 5개 — 시즌·페어 종류별로 다이내믹할지
