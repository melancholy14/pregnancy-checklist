# UX 스펙 — 홈

> 대상 영역: 홈 (`/`) — 진입 첫 화면, 온보딩 + 예정일 입력 + 대시보드 + 미니 그리드
> 페르소나/원칙: [../persona.md](../persona.md)
> 시각 토큰/UI 매핑: [ui.md](ui.md)
> 알려진 위반/개선 백로그: 본 문서 §10

---

## 1. 한 줄 정의

**"내가 어디까지 챙겼고, 다음에 뭘 할지"를 첫 진입에서 즉시 답해주는 개인화 대시보드.** 예정일 미입력 시에는 입력 유도가 핵심이고, 입력 완료 후에는 주차 컨텍스트 + 4개 핵심 기능(체크리스트·타임라인·체중·정보)으로 분기시키는 허브 역할.

---

## 2. 사용자 목표 (Jobs-to-be-Done)

| 시점 | 사용자 의도 | 홈이 해줘야 하는 것 |
|------|-------------|---------------------|
| **첫 방문 (예정일 미입력)** | "이 사이트가 나한테 뭘 해줘?" | 온보딩 → 예정일 입력 → 즉시 가치 (현재 주차 표시) |
| **재방문 (예정일 입력 후)** | "지금 내가 어디쯤이지?" | 현재 주차 + D-day + 진행률 한 화면에 |
| **재방문 (이번 주 작업)** | "이번 주 뭐 해야 해?" | 이번 주 할 일 카드 (최대 3개) → 타임라인 진입 |
| **재방문 (다른 기능)** | "체중 기록하고 싶어" / "정보 보고 싶어" | 미니 대시보드 그리드 → 4개 영역으로 분기 |

핵심 행동 = **예정일 입력**(첫 방문) / **체크리스트·타임라인 진입**(재방문). 홈은 자체 가치 생성보다 **다른 영역으로 보내는 디스패처**.

---

## 3. 정보 구조 (IA)

```
/ (홈)
├─ Hero (그라디언트 로고 + h1 + 라인)
├─ DueDateInput (예정일 입력)
├─ [예정일 입력됨]
│   ├─ 재방문 웰컴 배너 (선택, 1회성)
│   ├─ 2×1 정보: 현재 주차 / D-day
│   ├─ 체크리스트 진행률 카드 ──→ /timeline
│   └─ 이번주 할 일 카드 (3개 미리보기) ──→ /timeline
├─ [예정일 미입력] 노란색 안내 팁
├─ 미니 대시보드 2×2
│   ├─ 베이비페어 ──→ /baby-fair
│   ├─ 체중 기록 ──→ /weight
│   ├─ 영상 ──→ /info?tab=videos
│   └─ 정보 & 가이드 ──→ /info
└─ 동기 부여 텍스트 (BRAND_COPY.motivation)
```

### 3.1 분기 원칙

- **예정일은 게이트.** 입력 전에는 대시보드 영역 자체가 없음. 입력 후에 한 번에 풍부해짐.
- **재방문 웰컴은 1회성.** 같은 세션에 반복 노출하지 않음(localStorage `due-date-toast-shown`).
- **미니 대시보드 4개는 동급.** 시각적 비중이 같아야 사용자가 자유롭게 분기 가능. 하나만 강조하면 IA가 깨짐.

## 4. 상태 모델

| 상태 | 발생 조건 | 처리 |
|------|----------|------|
| **온보딩 표시** | 첫 방문 (`onboarding-completed` 미설정) | 전체 페이지를 OnboardingFlow로 전환 |
| **예정일 미입력** | `dueDate` 비어있음 | Hero + DueDateInput + 노란 팁 + 미니 그리드만. 대시보드 영역 자체가 안 그려짐 |
| **예정일 입력 직후** | dueDate 신규 설정 | 토스트 1회 노출 (`due-date-toast-shown`). 대시보드 즉시 펼침 |
| **재방문 (24h↑ 경과)** | `last-visit-date`가 어제 이전 | 웰컴 배너 표시 |
| **미하이드레이션** | localStorage 읽기 전 | 진행률 0%, 체크 0개. SSR 깜빡임 회피를 위해 인적션 안전 처리 필수 |
| **정상** | dueDate 있음, hydrated | 모든 카드 풍부 표시 |

### 4.1 상태 전환

- 예정일 입력 → 즉시 GA `due_date_set` + 대시보드 펼침 (페이지 리로드 없음)
- 예정일 변경 → DueDateInput 안의 input value 변경. 별도 confirm 없음 (실수 위험 있음)

## 5. 인터랙션 패턴

### 5.1 예정일 입력

- **트리거**: native `<input type="date">` 변경 이벤트
- **피드백**: 즉시 store 업데이트 + 현재 주차 Badge 노출 + 1회성 토스트
- **유효성**: 별도 검증 없음 (과거/미래 둘 다 허용 — 의도된 자유도)
- **변경**: 실수 변경 시 복구 불가 — 결정 대기 항목 §10

### 5.2 카드 클릭 (Link 래퍼)

- 모든 대시보드 카드는 통째로 `<Link>`. 카드 어디를 눌러도 동일 라우트로 이동.
- hover: `shadow-md` + `-translate-y-0.5` (살짝 떠오름)
- 키보드 Tab으로 도달, Enter로 진입

### 5.3 이번주 할 일 미리보기

- **체크박스는 비활성** (`pointer-events-none`). 시각 전용.
- **CTA**: "타임라인에서 확인하기" 버튼 — 실제 토글은 타임라인에서.
- 의도: 홈에서 직접 토글하면 이번주 카드의 정보 의미가 사라짐(체크 시 사라지면 됨). 그래서 의도적으로 보여주기만 하고 행동은 위임.

### 5.4 BottomNav

- 홈은 BottomNav의 첫 항목. `bg-pastel-pink/40` 활성 상태.
- 다른 페이지에서 BottomNav로 홈 복귀 시 페이지 상태(스크롤·hydration) 보존되어야 함 — Next App Router 기본 동작에 의존.

## 6. 접근성 스펙

| 항목 | 합격 기준 |
|------|-----------|
| **키보드 내비** | DueDateInput → 대시보드 카드 4개(또는 미입력 시 안내 → 미니 그리드 4개) → BottomNav. Tab 순서가 IA 순서와 일치. |
| **스크린리더** | 카드 라벨에 목적지 명시 ("체크리스트 진행률, 타임라인으로 이동"). 진행률은 텍스트로도 ("8/32 완료"). |
| **색 대비** | 그라디언트 hero 위 h1 텍스트 대비 측정 필요 (pink/lavender/mint 위 foreground 텍스트). |
| **터치 타겟** | 모든 카드 ≥ 44×44px. DueDateInput ≥ 44px 높이. |
| **focus visible** | 카드 hover scale + ring. `focus-visible:ring-2 focus-visible:ring-pastel-pink/60` 권장. |

## 7. 마이크로카피 원칙

- **격려 1줄 + 액션 1줄**. "출산 예정일을 입력하세요" + 보조 설명.
- **재방문 웰컴**: "다시 오셨네요!" 같은 친근한 톤. 단 매번 말고 1회성.
- **미입력 안내 팁**: "예정일을 입력하면 ___을 볼 수 있어요" — 미래 가치 명시.
- **미니 대시보드 카드**: 라벨 + 한 줄 부제. 부제는 "지금 ___" 형태로 행동 유도.
- **이모지는 의미 동반 시만**. Hero는 이모지 없음(그라디언트 로고가 시그니처). 미니 카드는 영역 시그니처 이모지 1개.

---

## 8. 데이터·저장 모델 (UX 관점)

- **dueDate**: localStorage `due-date-storage` (Zustand persist).
- **onboarding-completed**: localStorage 단순 boolean.
- **last-visit-date**: 재방문 배너 트리거. 매 방문 시 갱신.
- **due-date-toast-shown**: 토스트 1회만. 사용자가 dueDate 변경하면 다시 표시할지는 결정 필요.
- **다른 영역 store** (checklist, timeline, weight)는 홈에서 **읽기만**. 홈에서 데이터 변경하지 않음.

## 9. 성공 측정

| UX 가설 | 측정 이벤트 |
|---------|-------------|
| 첫 방문자가 예정일을 입력한다 | `due_date_set { source: "home" }` / 첫 세션 |
| 재방문자가 다음 행동으로 분기한다 | 홈 → 다른 라우트 전환률 (GA outbound nav) |
| 미니 대시보드 4개 중 어디로 분기하나 | 카드별 클릭 분포 (`cta_click { location: "home_minigrid" }`) |
| 이번주 할 일 카드가 타임라인 진입을 만든다 | "타임라인에서 확인하기" CTA 클릭률 |
| 웰컴 배너가 재방문 가치를 만드나 | 배너 노출 → 카드 클릭 전환률 |

## 10. 알려진 UX 이슈 / 결정 대기

- [ ] **(M)** 예정일 변경 시 confirm 다이얼로그 추가 여부 — 현재는 즉시 반영, 실수 변경 복구 불가
- [ ] **(M)** 재방문 웰컴 배너의 트리거 조건 명확화 — 24h 경과 vs 첫 진입 vs 새 주차 진입 중 어느 것?
- [ ] **(L)** "이번주 할 일" 미리보기 개수 (현재 3개) — 디바이스/주차에 따라 가변할지
- [ ] **(L)** 미니 대시보드 카드 순서가 사용 빈도와 일치하는가 (체중을 더 위로 올릴지) — GA 데이터로 검증
- [ ] **(M)** 미니 그리드 4번째 카드의 색이 토큰 외(`#E0F0FF`) — UI 위반과 동시 결정 필요. UI 측: [ui.md §10](ui.md)
- [ ] **(L)** Hero 그라디언트 로고가 페이지의 첫 시각적 무게점인데, 사용자가 그게 "이 사이트의 아이덴티티"인지 인지하는가

## 11. 변경 가이드

이 문서를 갱신하는 시점:

1. 미니 대시보드 카드 추가/삭제·순서 변경 (§3 IA)
2. 온보딩 / 예정일 게이트 로직 변경 (§4 상태 모델)
3. 새 카드의 인터랙션 추가 (§5)
4. 결정 대기 항목 해소 시 → §10 체크박스 닫고 본문 반영

UI 토큰·시각 적용은 [ui.md](ui.md)에서 별도 관리.
