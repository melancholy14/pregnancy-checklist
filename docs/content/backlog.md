## 분류 기준

- **🟥 차단**: 의사결정 / 선행조건 부재로 멈춰 있음. 의사결정 시 즉시 진행 가능

## A. Phase 4 → Phase 5 이월

> 출처: [`docs/plan/phase-4.md`](../plan/phase-4.md) §"Phase 5로 이동된 항목"

### A1. 체중 차트 BMI별 권장 범위 시각화 🟧

- 구 Phase 4 Step 1. 임신 전 키/체중 입력 → BMI 자동 계산 → IOM 2009 권장 범위 영역 그래프
- **이동 이유**: 법적 리스크 HIGH(YMYL 의료, 의료기기법 저촉 가능), 구현 비용 HIGH, AdSense 승인과 직접 무관
- **선행 조건**: 의료 면책 프레임워크 강화, 개인정보처리방침 건강정보 조항, IOM 2009 데이터 정리
- **재평가 시점**: AdSense 운영이 안정화된 뒤 (Phase 5 도구 고도화 단계)

### A2. 영상 채널 디렉토리 페이지 🟧

- `/info/channels` 또는 `/channels` 별도 라우트
- **이동 이유**: `/info` 통합에서 채널 카드를 콘텐츠 카드와 섞으면 정체성·필터·AdSense 관점 모두 약화
- **선행 조건**: `/info` 통합 안착, 채널 큐레이션 정책(검증 기준·분류) 정리
- **AC**: 채널 디렉토리 카테고리 필터 + 채널 상세에서 해당 채널 영상 리스트, 영상 카드 채널명 → 채널 상세 deep link
- **재평가 시점**: `/info` 사용 패턴(검색·필터 비율) 데이터 1개월 누적 후

### A3. 통합 태그 2단계 계층 필터 (옵션 B) 🟧

- 1차 필터(통합 태그) 선택 시 2차 sub-tag 펼침
- **이동 이유**: 현재 콘텐츠 규모(블로그 8 + 영상 57)에서 단일층 필터로 충분
- **선행 조건**: 블로그 20개+ 또는 영상 100개+
- **재평가 시점**: 블로그 ≥20건 또는 0-결과 검색이 sub-tag 부재로 인한 것이라는 신호 발생 시

### A4. 큐레이션 컬렉션 카드 (옵션 D) 🟩

- "출산 전 한 달 필독 10선" 같은 편집자형 컬렉션
- **이동 이유**: 운영 리듬이 잡혀야 가치 발생. ROI 낮음
- **선행 조건**: 콘텐츠 추가 빈도 안정, `collections.json` 스키마
- **AdSense 효과**: thin content 회피 + 신뢰도

### A5. 블로그 front matter 태그 정규화 마이그레이션 🟨

- 현재는 `unified-tags.ts` 런타임 동의어 매핑으로 흡수
- **이동 이유**: 인덱싱·운영 안정성 보호
- **재평가 시점**: 통합 태그 정의 안착 + SEO 영향 모니터링 후
- **자동 흡수 조건**: 마이그레이션 스크립트 1회 실행 + 동의어 매핑 안전망 유지

### A6. 영상 sub-category 진입점 🟨

- **이동 이유**: 검색(`fuse.js`)으로 도달 가능
- **자동 흡수 조건**: A3 옵션 B 또는 A2 채널 상세 내부 필터로 흡수

### A7. 크로스링크 영역 확장 🟨 — 사실상 자동화로 해소됨

- 영상↔타임라인/블로그, 베이비페어↔타임라인/블로그
- **상태**: Phase 4 Step 5 자동 스크립트로 매핑은 자동 생성. **다만 양방향 대칭성 검증·UI 노출은 별도 확인 필요**
- **재평가 시점**: 측정 이벤트(`related_*_click`) 도입 후 클릭률 데이터로 가치 검증

### A8. 영상 데이터 `registered_date` 백필 ✅ (해소)

- Phase 4에서 운영자가 57건 직접 백필 + `upload_date`/`is_short` 필드 추가. **해소됨**

## B. Phase 4.5 미정의 영역

> 출처: [`docs/plan/phase-4.5.md`](../plan/phase-4.5.md) §3·§4

### B1. 임신 주차 입력(onboarding) UX 🟥

- 현재 사이트에 사용자가 due date·주차를 명시 입력할 곳이 없음
- **차단 영향**: GA4 user properties(`due_date_set`, `current_pregnancy_week`, `cohort_join_week`)가 작동 불가 → §1.8 묶음 G·H 진행 막힘
- **연결 결정**: §2.6 D-day 컨텍스트 라벨, §3 P2 isHighlighted 부활
- **재평가 시점**: Phase 4.5 §3 N묶음 결정 시 즉시

### B2. localStorage schema versioning 🟥

- zustand `persist`에 schema version 필드 없음. P1 결정 후 마이그레이션 함수 도입 필요
- **차단 영향**: P1 priority 편집 허용·P2 isHighlighted 부활 시 데이터 호환성
- **재평가 시점**: P1 결정 직후

### B3. 데이터 모델 의미 모호 — `recommendedWeek: 0` 🟥

- 0이 "시점 무관"인지 "주차 미정"인지 코드에서 분리 안 됨
- **차단 영향**: P2가 "부활"로 결정되면 모든 항목이 매주 추천되는 잠재 버그
- **재평가 시점**: P2 결정 직후 또는 그 전에 의미 정의

### B4. `note` 필드의 콘텐츠 타입 분류 🟧

- "병원 전화 확인" / "도로교통법 제50조" / "제왕절개 시" 등 성격 다른 노트가 한 필드에
- **자동 흡수 조건**: §2.6 UX 기회 #5 ("노트 → 자동 액션 분리") 진행 시 `note_type` 필드 도입
- **재평가 시점**: 노트 활용 UX 기획 시

### B5. 카테고리 두 체계 공존 🟩

- timeline용 6개 글로벌 카테고리 vs 신규 체크리스트 3종의 로컬 subcategories 공존
- **이동 이유**: 단기 영향 작음. 통합 검색·필터 만들 때 결정
- **재평가 시점**: Phase 5 통합 검색·필터 착수 시

### B6. 운영자 가이드 — 체크리스트 데이터 변경 룰 🟧

- 항목 ID 변경/삭제 시 사용자 localStorage에 dangling 발생
- **현재 갭**: Phase 4 Step 5의 운영 절차는 자동 크로스링크만 다룸. 체크리스트 항목 변경 룰은 문서화 안 됨
- **재평가 시점**: 운영 1회 사고 발생 또는 데이터 변경 빈도 증가 시

### B7. 빈 상태(empty state) 정책 🟧

- GA4 `empty_state_view`가 측정 항목인데 빈 상태 케이스·코피·CTA 정의 안 됨
- **케이스**: 첫 방문 / 모두 체크 / 마이그레이션 후 사라진 데이터 / 커스텀만 있을 때
- **재평가 시점**: §1.8 묶음 J(신호 이벤트) 도입 시 함께
