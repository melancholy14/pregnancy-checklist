## 1. 기능 요약

§1.5 `empty_state_view`가 측정 항목인데 정작 빈 상태가 어떤 페이지에 어떤 형태로 보이는지 미정의. 4종 케이스 카피·CTA·시안 강도 결정. (1) 첫 방문(체크 0개), (2) 모두 체크 완료, (3) 마이그레이션 후 데이터 사라짐, (4) 커스텀만 있고 기본 0개. §1.8 묶음 J(신호 이벤트) 도입과의 묶음 의존성, P3(임신 주차 입력 onboarding) 결정 의존성 존재.

## 2. 적용 페어 + 선택 이유

- **planner × designer** — 충돌 축: "본질 도구 가치 노출 강도(주차 안내·다음 행동 명시)" vs "임산부 민감 시기 인지 부하·정보 중복 회피". 4종 케이스 각각의 카피·CTA·시안 강도 핵심 충돌.

제외한 페어:
- planner × marketer: §7.7(planner) ↔ §3.3(marketer) 공포 마케팅 거부 룰 합치 — 충돌보다 협력 축.
- designer × marketer: AdSense thin content 우려는 카피 충실도로 자동 해소 — 약함.
- dev 페어: 컴포넌트 구현 비용은 기존 article-prose 패턴 활용으로 작음 — 충돌 약함.

**[planner] 단독 입장**
- 잃는 것: 빈 상태 시안 단순함, 임산부 톤 부드러움(데이터 손실 케이스에서 명시 카피 강도↑로 인한 불안 자극 가능성)
- 양보 거부 인용: "**7.5 체크리스트 = 본질 도구 우선**" — docs/content/persona.md §7.5. 빈 상태도 본질 도구 안내 기회. "**7.1 사용자 데이터 무결성 — localStorage 스키마 변경은 migrate 함수 없이 배포 금지**" — §7.1. 마이그레이션 손실은 사용자가 명시 인지해야 함. "**7.6 측정 없는 기능 도입 거부**" — §7.6. 4종 케이스 각각 `empty_state_view.case` 파라미터로 분류 발사 의무. "**7.7 공포 마케팅 거부 — '이거 모르면 큰일 나요' 류 거부**" — §7.7. "다음에 챙길 게 더 있어요" 식 압박 표현 거부.
- 주장:
  - **첫 방문**: "주차 입력하면 더 잘 보여드려요" 보조 CTA. P3·P4 결정 종속이지만 P9에서는 카피 패턴만 명세.
  - **모두 완료**: 격려 카피 + 다음 행동 제안 (다른 체크리스트·관련 글 1~2개). 공포 톤 거부.
  - **마이그레이션 손실**: 명시 카피 — "이전 체크 기록을 불러오지 못했어요. 항목은 그대로 있으니 다시 체크해 주세요." 자동 복구 실패 시에만 표시.
  - **custom만**: "기본 항목이 갱신 중이에요. 추가하신 항목은 그대로 보여드릴게요." 운영자 SOP(P10 가이드)에 deprecated 플래그 룰 동반 도입.
  - GA4: `empty_state_view`에 `case: first_visit | all_done | migration_lost | custom_only` + `page` 파라미터. §1.8 J와 동시 도입.
- 잔재 자기검증: 이전 페어 없음 — N

**[designer] 반박 입장**
- A 발언 명시 반박 1: "주차 입력 보조 CTA는 P3 결정 종속이라 P9에서 명세 의미가 약함. P3가 풀스크린 onboarding으로 결정나면 빈 상태에서 같은 입력 CTA를 또 박는 건 §3 원칙 5 '같은 정보 중복 표시 금지' 위반. P9 첫 방문 시안은 P3 결정 후 갱신 명시 또는 묶음으로 deferred."
- A 발언 명시 반박 2: "'모두 완료' 케이스에 별도 시안 띄우기는 정보 중복 가능성. 체크된 항목은 strikethrough로 이미 시각화돼 있고 사용자는 '내가 다 체크했다'를 직접 인지함. 별도 빈 상태(일러스트 + 격려 카피 + CTA) 띄우면 N4 가짜 진행률·게이미피케이션 함정 진입 위험. **상단 짧은 격려 토스트 또는 헤더 미세 변경**으로 충분."
- A 발언 명시 반박 3: "마이그레이션 손실 카피의 '명시 강도'가 핵심. '이전 체크 기록을 불러오지 못했어요'는 임산부 사용자에게 불안 자극 — '체크 기록을 새로 시작해요. 항목은 그대로 보여드릴게요' 처럼 손실보다 **재시작에 초점**. 자동 복구 시도 우선(zustand `persist`의 `onRehydrateStorage` 콜백에서 실패 캐치) 후 명시 카피는 폴백."
- 잃는 것: 본질 도구 안내 강도(첫 방문 보조 CTA 다운그레이드), 데이터 손실 가시성 일부(마이그레이션 카피 부드러움)
- 희생 거부 인용: "**§3 원칙 5 — 인지 부하 최소화. 한 화면에 결정 1개. 같은 정보 중복 표시 금지**" — docs/design/persona.md §3 원칙 5. "**N4 다크 패턴 거부 — 가짜 카운트·뱃지, 의도적 시각 위계 왜곡**" — N4. "**도메인 컨텍스트 — 신체 변화·민감 시기. 빨간 경고색·과도한 알림 지양**" — §2 표. AdSense — "도구 페이지에 텍스트 콘텐츠 부족 = thin content 위험" — 빈 상태에 일러스트만 띄우면 적용 가능, 카피 충실도 검토 필요.
- 주장:
  - **첫 방문**: P3 결정 후 갱신 명시 또는 묶음 deferred. P9 1차 명세는 "기본 안내 카피 + 둘러보기 CTA"만.
  - **모두 완료**: **별도 빈 상태 시안 미도입** — 헤더에 격려 텍스트 1줄("모든 항목을 챙기셨어요 ✓") 추가 정도.
  - **마이그레이션 손실**: 자동 복구 시도 우선. 실패 시 부드러운 재시작 카피.
  - **custom만**: planner 카피 동의 (운영 SOP 선결조건).
  - GA4 이벤트 발사 동의 — 단 빈 상태 컴포넌트 **마운트 시 1회**만 발사 (페이지 내 재방문 시 미발사).
- 잔재 자기검증: 이전 페어 없음 — N

**T3 핵심 충돌 + 숨은 가정**
- 핵심 충돌:
  - **첫 방문**: planner(주차 입력 보조 CTA) vs designer(P3 결정 후 갱신/묶음 deferred)
  - **모두 완료**: planner(별도 시안 + 다음 행동) vs designer(헤더 1줄 격려만)
  - **마이그레이션 손실**: planner(명시 손실 카피) vs designer(부드러운 재시작 카피)
  - **custom만**: 양쪽 합의 — 임시 상태 명시 카피
- 숨은 가정: 양쪽 다 "운영자가 빈 상태 발생 빈도를 모니터링한다"고 가정. `empty_state_view`가 §1.8 묶음 J에서 도입되지 않으면 P9는 §7.6 위반 — §1.8 J와 동시 도입 필수. "마이그레이션 손실은 드물게 발생"도 검증 안 됨 — P5 schema versioning 도입 후 측정 가능.

## 4. 미해결 트레이드오프

### 4.1 첫 방문 케이스 — 카피·CTA (P9-1)
- [x] **결정**: **옵션 A — 둘러보기 CTA만**
- P3 컨텍스트(2026-05-05 결정 완료, [pregnancy-week-onboarding](../pregnancy-week-onboarding/review.md) §5 항목 2): 홈은 풀스크린 onboarding, 다른 진입 페이지는 슬림 배너(닫기 가능, 글로벌 컴포넌트)가 due date 입력 유도 담당. → 빈 상태 컴포넌트가 또 입력 CTA를 박으면 §3 원칙 5 "정보 중복 표시 금지" 위반.
- 카피·CTA: "체크리스트가 비어 있어요. 항목을 살펴보시겠어요?" + **[둘러보기] 단일 CTA**. 입력 유도는 글로벌 슬림 배너에 위임.

### 4.2 모두 완료 케이스 — 시안 형태 (P9-2)
- [x] **결정**: **A + C 결합** — 헤더 격려 텍스트 1줄 + 다음 행동 제안 토스트 1회
- 별도 빈 상태 시안 **미도입**. 모든 항목 체크 완료 시 (1) 헤더에 격려 텍스트 노출(`모든 항목을 챙기셨어요 ✓`), (2) 다음 행동 제안은 토스트 3초 1회로 표시(예: `다른 체크리스트도 살펴보시겠어요?` + [둘러보기] 액션 토스트). 토스트는 같은 슬러그 내 마운트 1회만 발사 — 페이지 재진입 시 미발사.
- 근거: designer N4(가짜 진행률·게이미피케이션 함정 회피) + planner 7.5(다음 행동 제안) 양쪽 충족. 별도 시안으로 화면을 만드는 부담은 회피하면서 본질 도구 안내는 토스트로 노출.

### 4.3 마이그레이션 손실 케이스 — 카피 강도 (P9-3)
- [x] **결정**: **옵션 A — 부드러운 재시작 카피 + 자동 복구 시도 우선**
- 자동 복구는 zustand `persist`의 `onRehydrateStorage` 콜백에서 실패 캐치. 복구 성공 시 빈 상태 미표시. 실패 시에만 폴백 카피: `체크 기록을 새로 시작해요. 항목은 그대로 보여드릴게요.` + [확인] 단일 CTA.
- 톤 근거: designer 도메인 컨텍스트(신체 민감 시기) + N4 다크 패턴 거부. 손실 명시보다 재시작 초점이 임산부 사용자 톤에 정합. §7.1 사용자 데이터 무결성은 "자동 복구 시도 → 실패 시 명시"로 충족.

### 4.4 custom만 케이스 — 카피 (P9-4)
- [x] **결정**: **옵션 B — 단순 안내 카피**
- 카피: `기본 항목이 비어 있어요. 추가하신 항목은 그대로 보여드릴게요.` 운영 상태 톤(`갱신 중`) 미노출. P10 운영자 가이드 미선결 상태에서도 진행 가능.
- 트레이드오프 인정: 사용자가 "왜 비어 있는지" 추측 가능성 있음. P10 운영 가이드(deprecated 플래그 룰)가 향후 도입되면 카피 갱신 1회 검토.

### 4.5 §1.8 묶음 J 도입 시점 (P9-5)
- [x] **결정**: **옵션 B — P9 카피·시안 먼저, GA4는 §1.8 J에서 별도**
- §7.6 "측정 없는 기능 도입 거부" 룰의 임시 허용 — 본 결정은 P9 카피·시안 작업 범위를 단독으로 끝내고, `empty_state_view` 이벤트는 §1.8 묶음 J 작업 시 spec.md `case` 파라미터(`first_visit | all_done | migration_lost | custom_only`) + `page` 파라미터로 발사 컨텍스트 박음.
- spec.md에 §7.6 임시 위반 명시 + §1.8 J 합류 시점 unblock 조건 적음.

## 5. 결정

운영자 결정 완료 (2026-05-07):

- **4.1 첫 방문 케이스**: 옵션 A — 둘러보기 CTA만. 입력 유도는 P3 글로벌 슬림 배너에 위임.
- **4.2 모두 완료 케이스**: A + C 결합 — 헤더 격려 텍스트 1줄(`모든 항목을 챙기셨어요 ✓`) + 다음 행동 제안 토스트 1회(3초). 별도 빈 상태 시안 미도입.
- **4.3 마이그레이션 손실 케이스**: 옵션 A — 자동 복구 시도 우선(`onRehydrateStorage` 콜백), 실패 시 부드러운 재시작 카피 폴백.

- **4.5 §1.8 묶음 J 도입 시점**: 옵션 B — P9 카피·시안 먼저, GA4 `empty_state_view`는 §1.8 J 작업 시 별도 도입. §7.6 임시 위반 명시.

## 6. 우선순위 영향

- **P3·P4 임신 주차 입력 onboarding** — 4.1=B 또는 C 선택 시 직접 묶음. 4.1=A는 P3 결정 후 P9 갱신 1회.

- **체크리스트 데이터 모델 묶음 (P1·P2·P5·P6·P7·§2.3 C1)** — 4.3 결정과 P5 인프라 일부 공유. 묶음 결정 시 P9 4.3 옵션 재검증 필요.
