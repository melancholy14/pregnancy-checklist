## review.md 결정사항 참조

본 스펙은 review.md §5 결정에 일관되게 따른다. 결정 본문이 어긋날 시 review.md 우선.

- **4.1 첫 방문**: 둘러보기 CTA만. 입력 유도는 P3 글로벌 슬림 배너에 위임 — 빈 상태에서 입력 CTA 중복 금지.
- **4.2 모두 완료**: 헤더 격려 텍스트 1줄(`모든 항목을 챙기셨어요 ✓`) + 다음 행동 제안 토스트 1회(3초). 별도 빈 상태 시안 미도입.
- **4.3 마이그레이션 손실**: 자동 복구 시도(`onRehydrateStorage` 콜백) 우선. 실패 시 부드러운 재시작 카피 폴백.
- **4.4 custom만**: 단순 안내 카피, 운영 톤 미노출.
- **4.5 §1.8 묶음 J**: GA4 이벤트 분리 — P9는 카피·시안 먼저, `empty_state_view`는 §1.8 J 작업 시 도입.

## 1. 배경·목적

- **운영자 관점**: §1.5 `empty_state_view`가 측정 항목으로 정의됐으나 빈 상태 자체의 카피·시안·발사 컨텍스트 미정의. 신규 글·신규 기능 추가 시 빈 상태 처리가 임시 직관에 의존.
- **사용자 관점**: 임산부 사용자가 체크리스트·정보 페이지 진입 시 본문이 비어 있으면 "왜 비었는지·다음에 뭐 하는지" 안내 부재 — 본질 도구 가치 훼손 가능성.
- **측정 관점**: §1.8 묶음 J(신호 이벤트) 도입 시 `empty_state_view.case`로 4종 케이스 발생률·페이지별 분포 측정 가능. 본 결정은 카피·시안만, GA4는 §1.8 J에서 별도.

## 2. 사용자 시나리오

- **시나리오 1 (첫 방문 — SEO 직진자)**: 사용자가 검색을 통해 체크리스트 상세 페이지로 직접 진입. 글로벌 슬림 배너(P3 결정)가 헤더에 떠 있어 due date 입력 유도 담당. 본문 영역은 체크 0개 상태로 빈 상태 컴포넌트가 렌더 — `체크리스트가 비어 있어요. 항목을 살펴보시겠어요?` + [둘러보기] 단일 CTA. 사용자가 [둘러보기] 탭하면 체크리스트 항목 리스트로 스크롤·전환.
- **시나리오 2 (모두 완료)**: 사용자가 모든 항목을 체크하면 (1) 체크리스트 헤더에 격려 텍스트(`모든 항목을 챙기셨어요 ✓`) 추가 노출, (2) 토스트 3초 1회(`다른 체크리스트도 살펴보시겠어요?` + [둘러보기] 액션). 토스트는 같은 슬러그 마운트 1회만 — 페이지 재진입 시 미발사. 별도 빈 상태 화면 전환 없음.
- **시나리오 3 (마이그레이션 손실)**: zustand `persist` 하이드레이션 시 schema 불일치 또는 손상으로 `onRehydrateStorage` 콜백이 실패 캐치. 자동 복구 시도(default initial state로 재초기화) 후 페이지 정상 렌더. 사용자에게는 부드러운 폴백 카피 1회 노출 (체크리스트 페이지 본문 상단 inline alert): `체크 기록을 새로 시작해요. 항목은 그대로 보여드릴게요.` + [확인] 단일 CTA. CTA 탭 또는 첫 체크 시 alert 사라짐.
- **시나리오 4 (custom만)**: 운영자가 checklist_items.json 기본 항목을 일괄 deprecated로 변경하거나 데이터 갱신 중인 케이스. 사용자에게는 `기본 항목이 비어 있어요. 추가하신 항목은 그대로 보여드릴게요.` 단순 안내. CTA 없음(custom 항목은 그대로 노출되므로 다음 행동 명확).

## 3. 기능 요구사항

### must

- **빈 상태 컴포넌트 신규**: `components/checklist/ChecklistEmptyState.tsx` — `case` prop(`first_visit | migration_lost | custom_only`)으로 분기. `all_done` 케이스는 별도 시안 미도입(헤더 텍스트 + 토스트).
- **모두 완료 헤더 격려**: 체크리스트 헤더 컴포넌트(예: [ChecklistHub.tsx](../../../src/components/checklist/ChecklistHub.tsx) 또는 슬러그별 상세 페이지 헤더)에 모든 항목 체크 완료 시 `모든 항목을 챙기셨어요 ✓` 텍스트 노출. mint(success) 토큰 사용.
- **모두 완료 토스트**: 같은 슬러그 마운트당 1회만 발사. 토스트 라이브러리는 기존 사용 중인 것 활용(미사용 시 가벼운 inline 토스트 유틸 신규). 텍스트 + 액션 버튼 패턴.
- **자동 복구 콜백**: zustand `persist`의 `onRehydrateStorage` 옵션을 [createChecklistStore.ts](../../../src/store/createChecklistStore.ts)에 추가 — hydration 실패 시 default state로 재초기화하고 별도 store 키(예: `migrationLostFlag`)에 1회 표시. 빈 상태 컴포넌트가 `migration_lost` 케이스로 분기 시 이 플래그 참조.
- **카피 정합성**: 4종 케이스 카피는 review.md §5 결정 그대로. 임의 변형 금지(designer 페르소나 6.6 임의 결정 X). 카피 변경 필요 시 review.md 갱신 후 spec 동기화.
- **§1.8 J 합류 unblock 조건 명시**: §1.8 묶음 J 작업 시작 시 P9 spec.md 본 섹션 참조 → `empty_state_view` 이벤트 추가:
  - `event_name`: `empty_state_view`
  - `case`: `first_visit | all_done | migration_lost | custom_only`
  - `page`: 페이지 식별자(슬러그 또는 path)
  - 발사 컨텍스트: 빈 상태 컴포넌트 마운트 시 1회 (중복 발사 금지)

### should

- **a11y**: 빈 상태 컴포넌트는 `<section role="status" aria-live="polite">` 또는 동등 시맨틱. 토스트는 `role="status"`. 헤더 격려 텍스트는 정적 — 별도 라이브 영역 아님.
- **모바일 320px**: 카피 줄바꿈 자연스러움 검증(`word-break: keep-all`). 토스트 폭 화면의 90% 이내.
- **다크 패턴 점검**: 모두 완료 토스트가 다른 체크리스트 광고로 보이지 않게 — designer N4·planner 7.7 룰 정합. 토스트 액션은 자체 도구 안내만.

### won't (이번 범위 밖)

- **GA4 `empty_state_view` 이벤트 코드 추가**: §1.8 묶음 J에서 별도 도입(4.5 결정). 본 PR은 이벤트 발사 코드 미포함, 단 컴포넌트 마운트 hook 위치는 §1.8 J 합류 시 즉시 사용 가능하도록 spec.md §3 must 참고용으로 박음.
- **첫 방문 입력 유도 카피**: P3 글로벌 슬림 배너가 담당. P9 빈 상태 컴포넌트는 둘러보기 CTA만.
- **모두 완료 별도 시안**: 사용자 결정으로 미도입. 향후 사용자 피드백·`empty_state_view.case=all_done` 발생률 데이터 누적 후 재검토.
- **다른 도메인 빈 상태**: 본 결정은 체크리스트 4종 케이스 한정. 정보 탭·체중 트래커·타임라인 빈 상태는 별도 결정 항목.
- **운영자 SOP P10 통합**: P10 운영자 가이드 작성은 별도 작업. 4.4 custom만 케이스의 운영 톤 미노출 결정은 P10 미선결 상태에서도 진행 가능.

## 4. 예외·엣지 케이스

- **모두 완료 → 항목 추가**: 사용자가 모든 항목 체크 후 새 custom 항목 추가하면 헤더 격려 텍스트 자동 사라짐. 토스트는 이미 발사됐으므로 재발사 X (마운트 단위).
- **모두 완료 → 체크 해제**: 헤더 격려 텍스트 자동 사라짐. 토스트는 마운트 단위라 영향 없음.
- **마이그레이션 손실 → 자동 복구 성공**: 빈 상태 컴포넌트 `migration_lost` 케이스 미렌더. 사용자 인지 없이 정상 동작 — 의도된 동작.
- **마이그레이션 손실 → 자동 복구 실패**: 폴백 카피 1회 노출. 사용자가 [확인] 또는 첫 체크 시 alert 사라짐. `migrationLostFlag` 클리어.
- **custom만 케이스 + 사용자가 custom 항목 0개**: 기본 항목 0 + custom 0 = 사실상 first_visit과 동일 — `first_visit` 케이스로 분기. 운영자 데이터 갱신 중이라는 사실을 사용자 시각으로 알 수 없음(P10 SOP 부재 영향).
- **localStorage 차단(시크릿 모드 등)**: zustand `persist` hydration 자체 미실행 → 메모리 상태로 동작. `migration_lost` 케이스 미트리거. 빈 상태는 `first_visit`으로 분기.
- **체크 toggle 직후 모두 완료**: 헤더 격려 텍스트 즉시 노출, 토스트는 다음 마운트까지 미발사 — 의도된 1회 룰. 사용자가 페이지를 떠났다 다시 들어오면 토스트 발사.

## 5. 성공 기준

- **기능 동작**:
  - 4종 케이스 모두 review.md §5 결정 카피·CTA로 렌더.
  - 자동 복구 콜백이 zustand `persist` 하이드레이션 실패 시 default state로 재초기화하고 사용자에게 폴백 카피 1회 노출.
  - 모두 완료 토스트 같은 슬러그 마운트당 1회 — 재방문 시 미발사 검증.
- **측정 지표**: P9 단독으로는 신규 GA4 이벤트 없음(4.5=B). §1.8 묶음 J 도입 후 1주 누적 — `empty_state_view.case=*` 발사율로 케이스별 발생률 확인. `case=all_done` 발사율이 낮으면(예: <5%) 별도 시안 미도입 결정 검증, 높으면 다음 행동 제안 강화 검토.
- **사용자 경험**: design.md §3 상태별 시안 충족. WCAG AA 색 대비, `role="status"` 시맨틱, 모바일 320px keep-all 줄바꿈 검증.
- **임의 결정 0**: 카피·CTA 텍스트는 review.md 결정 그대로. PR 리뷰 시 카피 차이 발견되면 즉시 review.md 동기화 또는 PR 차단.
