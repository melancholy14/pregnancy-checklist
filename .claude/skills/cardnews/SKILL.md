# cardnews

발행 글 1편을 인스타그램 카드뉴스(캐러셀 PNG) + 피드 캡션·해시태그로 바꾼다. 사이트와 **같은 디자인 토큰**(크림 + 5파스텔 + Pretendard)으로 렌더돼서, 계정과 사이트가 비주얼로 한 브랜드로 묶인다.

## 왜 이 스킬인가

이미 발행된 글은 검증된 콘텐츠다. 새로 쓰지 말고 **글의 구조(제목·H2·표·FAQ)를 그대로 카드로 접어라.** 인스타에서 가장 잘 먹는 건 숫자·표·"놓치면 손해" 프레임인데, 정보성 글에는 그게 이미 들어 있다. 스킬의 일은 새 글쓰기가 아니라 **정확한 발췌 + 인스타 문법으로 재배치**다.

## 전제: 파이프라인은 이미 있다

렌더 인프라는 [tools/cardnews/](../../../tools/cardnews/)에 산다. **건드리지 말고 사용만 한다:**

- `styles.css` — 카드 디자인 시스템 (globals.css 토큰 미러). 편집 금지.
- `render.mjs` — 데이터 → 카드 HTML 조립기.
- `export.mjs` — deck JSON을 읽어 카드별 1080×1350 PNG로 내보냄.
- `decks/*.json` — **내용**. 이 스킬이 만드는 산출물이 바로 이 파일이다.

너가 하는 건 딱 하나: **좋은 deck JSON을 쓰는 것.** 그다음 `export.mjs`를 돌리면 PNG가 떨어진다.

## 워크플로우

### 1. 글 읽기
`src/content/articles/<slug>.md` 전체를 읽는다. 특히:
- **frontmatter** `title`·`description`·`authorNote` → 표지 훅과 캡션의 재료
- **H2 소제목** → 본문 카드 헤드라인 후보
- **표·굵은 수치** → 스탯 박스 / 콜아웃 재료 (인스타에서 제일 잘 먹음)
- **"마감/기한/놓치면" 문장** → 저장각 카드
- **FAQ** → 본문 카드 또는 캡션 훅
- **전용 페이지 링크** → 본문에 `pregnancy-checklist.com/<path>` 형태의 링크가 있는지 확인한다(예: 베이비페어 글의 `/baby-fair`). 있으면 그게 이 글의 **바이오 링크 후보**다(4·산출물 보고에 제시). 랜딩이 곧 그 글/페이지가 되어 CTA와 어긋나지 않기 때문.

### 2. deck JSON 작성
`tools/cardnews/decks/<deck-slug>.json`에 쓴다. 필드 스펙·마크업·파스텔 역할은 [references/deck-schema.md](references/deck-schema.md)를 읽고 정확히 따른다.

카드 구성 원칙:
- **6~8장 권장 (인스타 캐러셀 최대 10장)**: 표지 1 + 본문 4~7 + CTA 1. 콘텐츠가 풍부하고 임팩트 카드를 더 넣어야 하면 9~10장도 괜찮다. 다만 stage-1은 운영 부담 최소가 목표라 억지로 늘리지 말고 "한 장 = 한 메시지"가 유지되는 선까지만.
- **한 장 = 한 메시지.** 글 문단을 욱여넣지 말고 토막 낸다.
- 표지 훅은 글 제목보다 세게. 단 **공포 마케팅 금지**("안 하면 큰일" X → "몰라서 놓치면 아까워요" O).
- **가장 임팩트 큰 숫자를 표지·스탯에 올려라.** 글에 수치가 여러 개면 저장·도달을 부르는 건 보통 **극단값**(최고가·총액·최장 기한)이다. 평균값은 안전하지만 스크롤을 못 멈춘다. 예: 산후조리원이면 전국 평균가(372만원)보다 **서울 특실 최고가(810만원)**가 표지 훅으로 훨씬 세다. 정확도를 위해 극단값임을 라벨로 밝혀라("서울 특실").
- 콜아웃·스탯은 **필요한 카드에만.** 한 카드에 콜아웃 + 스탯을 둘 다 넣으면 하단 여백이 빡빡해지니 되도록 하나만.

### 3. 캡션 + 해시태그
같은 deck JSON에 `caption`·`hashtags` 필드로 넣는다. `export.mjs`가 `INDEX.txt`에 복붙용으로 출력한다. 포맷은 [references/deck-schema.md](references/deck-schema.md) "캡션·해시태그" 절 참고.

### 4. PNG 내보내기
```bash
node tools/cardnews/export.mjs decks/<deck-slug>.json
```
→ `tools/cardnews/out/<deck-slug>/01.png … NN.png` + `INDEX.txt` 생성.

### 5. 눈으로 검증 (필수)
생성된 PNG 중 **표지 1장 + 콜아웃/스탯이 가장 빽빽한 본문 1장**을 Read로 열어 확인한다:
- 텍스트가 안전영역(가장자리 96px) 밖으로 넘치거나 잘리지 않는가
- 형광펜(`*..*`)이 의도한 단어에만 걸렸는가
- 수치가 글 본문과 정확히 일치하는가
문제가 보이면 deck JSON을 고치고 4번을 다시 돌린다.

## 절대 지킬 것 (근거)

- **수치 정확도**: 카드의 모든 숫자·금액·기한은 글 본문에서 그대로 가져온다. 인스타는 캡처·박제되므로 과장·추정은 신뢰를 통째로 깎는다.
- **CTA 정직**: 두 층위로 지킨다.
  1. **없는 기능 금지**: "우리 동네 지원금 조회"처럼 사이트에 없거나 개인화 기능처럼 오해 주는 약속을 하지 마라. CTA가 가리키는 건 **글에 실제로 있는 콘텐츠**여야 한다(g수 표·주차별 캘린더·비교 기준 등 — 글을 읽고 실재 확인).
  2. **랜딩 현실 반영**: 바이오 링크는 phase-4.8 단계 1에서 **홈으로** 떨어진다. 즉 사용자는 "카드 → 홈 → 그 글"로 한 번 더 이동해야 한다. 그러니 CTA는 랜딩이 곧 그 글인 것처럼 단정하지 말고 "프로필 링크에서 **전체 글** 확인" 정도로 둔다. **단, 글 본문에 전용 페이지(예: `/baby-fair`)가 있으면** 그걸 바이오 링크로 쓰면 랜딩-콘텐츠가 정확히 맞으니, 산출물 보고에서 "이 글은 바이오를 `/baby-fair`로 돌리면 랜딩이 딱 맞음"이라고 **운영자에게 제시**하라.
- **톤**: 옆집 언니/친한 친구. 정보는 정확, 말투는 부드럽게. "동료심사"·"경향성" 같은 학술 표현 X.
- **면책은 주제 맞춤**: 정책·금융 글이면 "정책 개편 시 변동 가능, voucher.go.kr 확인" 식 정책 면책. 의학 글이 아닌데 의학 면책을 붙이지 마라.
- **이모지**: 캡션·카드에 `⚠️` 쓰지 말고 `💡 📌 🔔 ✔️` 사용. (경고 이모지는 다른 파이프라인에서 disclaimer로 오인 추출됨.)
- **브랜드 고정값**: 러닝헤드 "출산 준비 체크리스트", 핸들 `@pregnancy.checklist`, 필명 뿌까뽀까(개발자·초산맘).

## 산출물 요약 (작업 끝에 사용자에게 보고)

- PNG 경로: `tools/cardnews/out/<deck-slug>/`
- 장수 + 각 장 역할 1줄
- 캡션·해시태그 위치 (`INDEX.txt`)
- **바이오 링크 제안**: 글에 전용 페이지가 있으면 그 경로를, 없으면 홈(`?utm_source=instagram&utm_medium=bio`)을 명시
- 검증에서 확인한 것 + 남은 판단(예: 표지 훅 더 세게 갈지)
- 참고: `out/`은 재생성물이라 커밋 대상 아님. deck JSON만 커밋.
